Why does this exist?

Realtek's driver never notices a card inserted after boot, and takes over two minutes to notice one being removed. The inbox USBSTOR driver can't start the device at all.

The real cause showed up in a trace of the reader's status word while a card was pulled and pushed back:

slot      status word    "SD present" bit
card in   0x0001         1
card out  0x0009         1      <- still "present"
card out  0x0001         1      <- no change at all
The card-detect bit is stuck at "present". On this board the controller's CD line never reports an empty slot. So soracard doesn't ask the slot. It asks the card. A ready card gets a status command (CMD13) at most every 500 ms; an empty slot gets an initialisation attempt every second. Whoever answers is there.

Install it

From a Windows machine with the WDK (setup in docs/BUILDING.md).

Heads up: the driver is test-signed, so the machine needs test signing on, which means Secure Boot off. There is no production signature.
  1. Turn on test signing and reboot: bcdedit /set testsigning on
  2. Create the signing certificate (once): tools\make_test_cert.ps1
  3. Build and sign the package: tools\build_storport.ps1 -Package -Release
  4. Install over the running reader: tools\deploy_live.ps1 -Release

To go back to Realtek's driver, run tools\teardown.ps1. It reinstalls the vendor driver and removes everything soracard put on the machine.

The protocol core builds and tests anywhere:

$ cargo test -p sora-core
test result: ok. 91 passed; 0 failed

What it can and can't do

Can do

  • Detect insert and removal promptly on a board whose card-detect line is broken
  • Run UHS-I cards at SDR50 with phase tuning, and fall back cleanly
  • Survive sleep, eject, the lock switch and a hard power-off
  • Explain itself through a detailed registry trace

Can't do

  • Go past USB 2.0 (about 33 MB/s); DDR50 and SDR104 aren't implemented
  • MMC, Memory Stick, xD or SDIO cards. SD memory cards only
  • Load without test signing
  • Promise anything about hardware it hasn't met: one RTS5129 (QFN24) and one card have been tested. 0BDA:0139 and 0BDA:0140 are in the INF but untested
it answers, or it isn't there.
